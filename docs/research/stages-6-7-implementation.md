# 第 6、7 项：敏感会话与有限自动保护

日期：2026-11-01。开发包 0.0.5；Bundle ID `dev.whisky.maclx`，macOS 15+。
此文记录本地实现与自动测试，不将合成客户端测试等同于真实会议软件验收。

## 敏感内容的数据边界

`AppKitPasteboard.readIfChanged()` 在读取 payload 前，继续拒绝
`ConcealedType`、`TransientType`、`AutoGeneratedType`。用户设置不能覆盖此规则。

`GeneralSettingsStore.sensitiveApps` 允许选择应用。默认忽略来自这些应用的新副本；
另行启用 `retainSensitiveCopies` 后，才将未带拒绝标记的新副本放入内存会话。
`CaptureClipboardChange.callAsFunction` 的顺序是：读取可捕获快照 → 排除应用 →
敏感应用分流 → 普通历史记录。明确排除优先。敏感分支不调用 History.recording、
HistoryStore.save、普通 presenter 或 undo。`ClipboardController.applySensitiveSources`
只改变后续捕获，不把旧记录重新分类或迁移；来源归属仍是上游的前台应用／菜单栏
拥有者估计，不能当成可信的密码识别器。

`SensitiveSessionStore` 仅发布 UUID 和揭示状态，私有地持有 payload 和 RTF 原始字节。
不持有持久化 store、logger、LinkPresentation、Quick Look、图片解码器或缩略图缓存。
最多 10 条、合计原始内容 16 MiB；超出时淘汰最旧条目，单条超过总预算直接丢弃。
每条捕获 120 秒后释放，每次主动显示最多 10 秒。使用单调时间和一个可重设的
单次 Timer；面板关闭、全局保护生效时撤销揭示，关闭面板后的旧菜单回调也不能
重新揭示。休眠、息屏、会话切换、应用退出和敏感策略修改会清空会话。

`SensitiveSessionView` 是独立的小型内容区域，默认仅显示通用占位符，无来源名、
标题或内容提示；右键和省略号菜单都能临时显示。富文本按纯文本显示，不解析附件；
图片本轮只允许显式复制到其他应用查看，不生成本地缩略图。没有搜索、编辑、拖拽、
置顶、文件导出或粘贴栈入口。链接和路径显示为普通文字，不请求网络或读取文件。
全局保护优先，不会因为单条揭示而绕过整窗占位保护；全局保护结束后仍保持单条隐藏。

复制只在面板可见、无全局保护且揭示租约未过期时进行；
`AppKitPasteboard.writeSensitive` 重新添加 concealed/transient 标记，避免遵守约定的
其他管理器再次记录。系统剪贴板是用户明确选择的导出，其他应用可能忽略标记。
释放 Swift 值不等于安全擦除，也不能保证 OS swap、系统窗口快照或外部应用没有副本。
本实现避免应用自身的磁盘持久化，不宣称硬件级的“内容永不触盘”。

## 自动检测与保护状态

`UseCases/Ports/SharingDetector.swift` 定义可替换的同步检测接口、实现类别
（publicAPI / experimental / manual）、三个状态及原因。`PrivacyController` 与
检测器无 AppKit 耦合，单独保存 `manualPrivacy` 和 `automaticPrivacy`；默认自动检测关闭。

有效保护 = 手动保护 OR 已启用的自动保护。开启自动检测时先以 unknown 预防性遮盖；
active 立即遮盖，unknown 继续遮盖。解除自动保护需要至少两次完整的
clearWithinCoverage 观察，且从连续 clear 起点经过 5 秒。新 active 或 unknown
会重置计时。多个来源中 active 优先于 unknown，unknown 优先于 clear；空来源集合
是 unknown。自动开启／关闭或共享结束均不会清除用户的手动选择。

设置、菜单栏 tooltip 与右键菜单显示真实状态，区分手动、检测到工具栏、等待稳定结束、
权限不足／检测不确定、以及“未检测到支持的工具栏，其他共享仍可能存在”。
可选全局快捷键明确标为切换**手动**隐私模式，避免被误解为关闭自动保护。
占位符本身不再错误地声称仅因手动模式而隐藏内容。

## 本轮公开检测器的覆盖范围

`PublicSharingDetector` 仅用公开 Accessibility API，检查以下精确 bundle ID 的
顶层 AXWindows / AXTitle，不遍历聊天、网页、文档、菜单或整个辅助功能树。

| 应用身份 | 正向信号 | 验证状态 |
| --- | --- | --- |
| `us.zoom.xos` | 精确标题 `as_toolbar` / `Zoom Share Statusbar Window` | 规则和合成输入已测试；真实客户端版本、语言与共享方式待验证 |
| `com.microsoft.teams` / `com.microsoft.teams2` | 精确标题 `Screen sharing toolbar` / `Sharing control bar` | 规则和合成输入已测试；真实客户端待验证 |

仅运行 Zoom／Teams、普通会议窗、包含“sharing”字样的用户标题或其他进程同名窗口
都不构成 active。没有候选进程不进行 AX IPC；有候选但未授权、读取失败、节点数量
超过预算或时间耗尽均返回 unknown，不返回系统“未共享”。只有设置中的授权按钮
会请求辅助功能权限；后台采样只检查授权，不自动弹窗。

这是依赖客户端 UI 的有限启发式实现，不是跨软件检测保证。工具栏隐藏、客户端更新、
语言差异、无障碍实现不完整均可能漏检；某些标题碰撞也可能误报。没有匹配只代表
本规则范围内未发现工具栏。本轮不检测系统屏幕共享、远程桌面、QuickTime／其他录屏、
浏览器 tab 或其他会议软件；不读取未文档化会话字典键，也不把“已获录屏权限”当成录制中。
重要共享应在开始前手动保护；采样／UI 更新有时延，不能保证开始共享的第一帧不泄露。

`SharingMonitor` 管理生命周期：串行 utility worker，最多一个采样在执行，事件合并，
generation 丢弃停止／重启／睡眠前的结果。应用启动、退出、切换及唤醒触发复查，
睡眠／息屏／会话退出停止采样并报告 unknown。单次 AX IPC timeout 50ms，每应用最多
16 个窗口、约 500ms 标题读取预算，最多 8 个候选。定时补偿在候选存在时 3 秒、
没有候选时 15 秒，带 tolerance；均在上次采样完成后安排。功能关闭时无 timer／observer。
这些是实现参数，不是已通过 Instruments 得出的低能耗结论。

## 研究和 API／许可取舍

研究结论沿用 phase-1-audit.md 第 7 节，补核对了原始实现：

- [Mica ScreenCaptureMonitor](https://github.com/Vedant-29/mica/blob/88428bec5896c41db4c1267d7a54cd7c03f25f2a/Sources/MicaCore/Monitors/ScreenCaptureMonitor.swift)：WindowServer 私有符号计数无法提供统一、稳定的捕获语义；未把该代码或符号接入产品。
- [Hush controller](https://github.com/stacksjs/hush/blob/0d71ad9939210bd6325f9fae48cfdcf59f8362c4/src/runtime/controller.ts) 与 [Craft screen_sharing.zig](https://github.com/home-lang/craft/blob/1fb96b37dc6c30a431570c0902df5aa8a70c911c/packages/zig/src/screen_sharing.zig)：借鉴“共享控件正向信号”和结束去抖的思路。未复制第三方实现，未采用未文档化会话字典键、宽泛窗口标题匹配和仅按进程判断共享的规则。
- [Craft sharing_accessibility.zig](https://github.com/home-lang/craft/blob/1fb96b37dc6c30a431570c0902df5aa8a70c911c/packages/zig/src/sharing_accessibility.zig)：核对 AX 超时、节点和时间预算、原生控件与网页内容的区别；本轮不做复杂浏览器树遍历。
- Apple [Capturing Displays](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/QuartzDisplayServicesConceptual/Articles/DisplayCapture.html) 明确 display capture 的独占显示语义，因此未用 CGDisplayIsCaptured 代替现代共享检测；[ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit) 管理本应用捕获，不能从可共享内容列表推断其他应用正在录屏。

`CGSIsScreenWatcherPresent` / `SLSIsScreenWatcherPresent` 仍仅在研究文档出现。
私有检测器必须单独获得用户确认后才可实现。没有新增依赖、第三方代码或品牌素材；
上游许可证、版权及 Git 历史保留，新增修改遵循原 GPL 授权。

## 测试与本机验收

自动测试使用独立 defaults、私有 NSPasteboard、临时 SQLite、合成应用列表与工具栏；
不读取真实剪贴板，不开启真实会议、不授予系统权限。重点覆盖：

- 敏感捕获分流、默认忽略、明确排除优先；DB/WAL 字节、目录文件清单不变，普通搜索、撤销和日志不含 canary。
- UUID-only 发布状态、120 秒释放、10 秒自动隐藏、10 条／16 MiB 预算、关闭面板的过期菜单动作、全局保护与恢复、显式复制标记。
- 手动保护持久化和优先级、unknown 保守处理、两次观察及 5 秒结束去抖、多来源合并。
- 正向工具栏规则、无候选／无权限／读取失败、IPC 串行、事件合并、停止后的旧结果、休眠恢复及真实单次计时器。
- 英／法／简体中文资源一致性与本机完整回归。

验证证据保存在 evidence/2026-11-01/stages-6-7-*。最终测试数量和覆盖率以该目录日志为准。
离屏窗口无法完整导出 SwiftUI 的原生辅助功能树，因此单条敏感会话的真实 VoiceOver 验收未完成；
已有整窗保护的 AppKit AX 屏障测试继续保留。真实客户端、锁屏后焦点行为与系统权限归属
仍需实际界面验收，不能以
模拟 AX 数据替代。性能验收建议在同一版本、合成历史、同一机器上，用 Instruments
Time Profiler / Allocations / Energy Log 分别记录自动关闭、开启无候选、候选空闲、
共享中、AX 超时、结束与睡眠恢复；每组固定时长，记录唤醒次数和遮盖／恢复时延。

手动验收顺序：先退出旧开发版，再解压 0.0.5；默认不会开启自动检测或内存保留。
添加一个用于合成内容的敏感应用，先验证默认忽略，再打开内存保留，复制无真实秘密的
文本测试右键揭示、10 秒恢复、2 分钟消失和手动全局保护。再单独选择是否开启有限
自动检测和授予辅助功能权限，记录客户端精确版本及共享 screen／window 类型。
